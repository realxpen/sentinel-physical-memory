# Information Architecture

## Primary navigation

Only three first-class destinations:

1. **Memory**
2. **Observe**
3. **Changes**

`Ask this environment` remains persistent/contextual. Profile/settings stay secondary.

## Memory

Purpose: understand what SENTINEL currently remembers.

Contains:

- environment identity
- current state summary
- semantic/spatial memory canvas
- remembered objects/conditions/relations
- evidence access
- timeline/history entry points
- contextual Ask conclusions

## Observe

Purpose: create the next grounded environmental state.

Contains:

- capture/upload entry
- evidence-frame extraction state
- observing / understanding / remembering status
- failure/uncertainty feedback

## Changes

Purpose: understand scan-to-scan difference and verification.

Contains:

- previous vs current state
- Reality Diff
- added / removed / moved / changed / resolved / uncertain events
- before/after evidence
- verification outcome

## Contextual layers

### Evidence drawer

Opened from a memory object/condition/change. Shows:

- observed claim
- evidence reference(s)
- confidence
- historical context where available
- interpretation separated from recommendation

### Ask response

Not a chat destination. A response should surface as a conclusion in context, with evidence/confidence and related state/object/condition links.

### Action plan

A focused plan view/layer tied to an identified condition. It is not a work-management suite in the MVP.

## First-use state

Main statement: **Give this place a memory.**

Primary action: **Observe environment**.

Do not fill the empty state with fake metrics or fake detections.
